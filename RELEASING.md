# Выпуск PDFwright

Текущая версия: **1.0.0** (в `package.json`), тег релиза: **v1.0.0**. Версии 0.1.0–0.3.0 не публиковались: 1.0.0 — первый выпуск.

## Как устроено обновление

Установленная программа по кнопке **Параметры → Обновления → Проверить обновления** читает `latest.yml` последнего опубликованного релиза `iHoooK/PDFwright` (electron-updater, провайдер GitHub, без токенов). Если версия в `latest.yml` новее, пользователь видит «Скачать и установить…»: установщик скачивается с GitHub, его sha512 сверяется с `latest.yml`, затем запускается мастер установки с подтверждением. Черновики и pre-release не предлагаются. Portable-версия только показывает ссылку на релиз.

Для обновлятора в релизе обязательны три файла с точными именами: `PDFwright-Setup-x64.exe`, `PDFwright-Setup-x64.exe.blockmap` и `latest.yml`. Остальные два (`PDFwright-Portable-x64.zip`, `SHA256SUMS.txt`) нужны людям.

## Первый выпуск 1.0.0

Версия в `package.json` уже 1.0.0, поэтому `npm version` не нужен: тег ставится вручную на проверенный коммит `main` с зелёным CI.

```bash
git tag -a v1.0.0 -m "Версия 1.0.0"
git push origin v1.0.0
```

Дальше — с шага 4 следующего раздела: workflow создаст черновик, вы проверяете и публикуете его.

## Выпустить новую версию

1. Обновите [RELEASE_NOTES.md](RELEASE_NOTES.md): он целиком станет описанием релиза.
2. Поднимите версию и создайте тег одной командой (она же делает коммит):

   ```bash
   npm version 1.0.1 -m "Версия %s"
   ```

3. Отправьте коммит вместе с тегом:

   ```bash
   git push --follow-tags
   ```

4. GitHub Actions (`.github/workflows/release.yml`) соберёт релиз командой `bash scripts/build-release.sh`, проверит, что тег совпадает с версией в `package.json`, и создаст **черновик** релиза `PDFwright v1.0.1` с пятью файлами.
5. Откройте [релизы](https://github.com/iHoooK/PDFwright/releases), проверьте черновик: описание, пять файлов, тег. Оставьте **Set as a pre-release** выключенным, включите **Set as the latest release** и нажмите **Publish release**.

Пока релиз остаётся черновиком, обновлятор его не видит, а предыдущая версия остаётся актуальной.

## Выпустить вручную

Если Actions недоступен, соберите релиз локально из Git Bash:

```bash
bash scripts/build-release.sh
```

Создайте релиз на GitHub руками: тег `v1.0.1` на том же коммите, заголовок `PDFwright v1.0.1`, описание из `RELEASE_NOTES.md`, и загрузите все пять файлов из папки `build/`. Имена файлов менять нельзя. Не используйте автоматический `Source code (zip)` вместо portable-версии.

## Проверить опубликованный выпуск

- На установленной предыдущей версии нажмите **Проверить обновления**: должна появиться новая версия с размером установщика. «Скачать и установить…» скачивает файл, показывает проверку sha512 и предлагает установить; после мастера программа запускается сама, настройки и недавние файлы сохраняются.
- На свежей версии проверка должна сообщить, что установлена актуальная версия.
- Portable-версия показывает ссылку на страницу релиза; обновляется распаковкой нового архива в новую папку. Данные лежат отдельно в `%APPDATA%\PDFwright`.

Подписи кода у установщика нет: при первом запуске SmartScreen может показать предупреждение «Неизвестный издатель». Это ожидаемо для 0.x и не влияет на проверку целостности обновлятором.
