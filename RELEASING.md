# Выпуск PDFwright

Текущая версия: **1.0.0** (в `package.json`), тег релиза: **v1.0.0**. Версии 0.1.0–0.3.0 не публиковались: 1.0.0 — первый выпуск.

## Как устроено обновление

Программа сама проверяет обновления через 10 секунд после запуска и раз в 12 часов (выключается в Параметрах), а также по кнопке **Параметры → Обновления → Проверить обновления**: читает `latest.yml` последнего опубликованного релиза `iHoooK/PDFwright` (electron-updater, провайдер GitHub, без токенов). Если версия в `latest.yml` новее, в окне появляется предупреждение «Доступна новая версия PDFwright» с кнопками «Обновить» и «Позже»; «Обновить» (или «Скачать и установить…» в Параметрах) начинает установку: установщик скачивается с GitHub, его sha512 сверяется с `latest.yml`, затем запускается мастер установки с подтверждением. Черновики и pre-release не предлагаются. Portable-версия только показывает ссылку на релиз.

Для обновлятора в релизе обязательны три файла с точными именами: `PDFwright-Setup-x64.exe`, `PDFwright-Setup-x64.exe.blockmap` и `latest.yml`. Остальные два (`PDFwright-Portable-x64.zip`, `SHA256SUMS.txt`) нужны людям.

## Первый выпуск 1.0.0

Версия в `package.json` уже 1.0.0, поэтому `npm version` не нужен: тег ставится вручную на проверенный коммит `main` с зелёным CI.

```bash
git tag -a v1.0.0 -m "Версия 1.0.0"
git push origin v1.0.0
```

Дальше — с шага 4 следующего раздела: workflow соберёт и опубликует релиз.

## Выпустить новую версию

1. Обновите [RELEASE_NOTES.md](RELEASE_NOTES.md): он целиком станет описанием релиза.
2. Поднимите версию и создайте тег одной командой (она же делает коммит):

   ```bash
   npm version 1.0.1 -m "Версия %s"
   ```

3. Отправьте коммит вместе с тегом:

   ```bash
   git push --follow-tags
   ```

4. GitHub Actions (`.github/workflows/release.yml`) соберёт релиз командой `bash scripts/build-release.sh`, проверит, что тег совпадает с версией в `package.json`, и сразу опубликует релиз `PDFwright v1.0.1` с пятью файлами как последний (latest). Примерно через 15–20 минут после push релиз появится на [странице релизов](https://github.com/iHoooK/PDFwright/releases), а установленные программы предупредят о новой версии при следующей проверке.
5. Откройте релиз и проверьте описание, пять файлов и тег. Если что-то не так, удалите релиз и тег на GitHub, исправьте ошибку и выпустите следующую версию: обновлятор видит только опубликованные релизы.

Ставьте тег только на проверенную версию: релиз публикуется без черновика.

## Выпустить вручную

Если Actions недоступен, соберите релиз локально из Git Bash:

```bash
bash scripts/build-release.sh
```

Создайте релиз на GitHub руками: тег `v1.0.1` на том же коммите, заголовок `PDFwright v1.0.1`, описание из `RELEASE_NOTES.md`, и загрузите все пять файлов из папки `build/`. Имена файлов менять нельзя. Не используйте автоматический `Source code (zip)` вместо portable-версии.

## Проверить опубликованный выпуск

- Запустите установленную предыдущую версию: примерно через 10 секунд должно появиться предупреждение о новой версии с размером установщика (или нажмите **Проверить обновления**). «Скачать и установить…» скачивает файл, показывает проверку sha512 и предлагает установить; после мастера программа запускается сама, настройки и недавние файлы сохраняются.
- На свежей версии проверка должна сообщить, что установлена актуальная версия.
- Portable-версия показывает ссылку на страницу релиза; обновляется распаковкой нового архива в новую папку. Данные лежат отдельно в `%APPDATA%\PDFwright`.

Подписи кода у установщика нет: при первом запуске SmartScreen может показать предупреждение «Неизвестный издатель». Это ожидаемо для 0.x и не влияет на проверку целостности обновлятором.
