# Выпуск PDFwright

Текущая версия: **1.0.0** (в `package.json`), тег релиза: **v1.0.0**. Версии 0.1.0–0.3.0 не публиковались: 1.0.0 — первый выпуск.

## Как устроено обновление

Программа сама проверяет обновления через 10 секунд после запуска и раз в 12 часов (выключается в Параметрах), а также по кнопке **Параметры → Обновления → Проверить обновления**: читает `latest.yml` последнего опубликованного релиза `iHoooK/PDFwright` (electron-updater, провайдер GitHub, без токенов). Если версия в `latest.yml` новее, в окне появляется предупреждение «Доступна новая версия PDFwright» с кнопками «Обновить» и «Позже»; «Обновить» (или «Скачать и установить…» в Параметрах) начинает установку: установщик скачивается с GitHub, его sha512 сверяется с `latest.yml`, затем запускается мастер установки с подтверждением. Черновики и pre-release не предлагаются. Portable-версия только показывает ссылку на релиз.

Для обновлятора в релизе обязательны три файла с точными именами: `PDFwright-Setup-x64.exe`, `PDFwright-Setup-x64.exe.blockmap` и `latest.yml`. Остальные два (`PDFwright-Portable-x64.zip`, `SHA256SUMS.txt`) нужны людям.

Программа для Mac проверяет обновления так же, но читает `latest-mac.yml`. Устанавливать обновление сама она не умеет (для этого нужна подпись Apple): предупреждение ведёт на страницу релиза, а пользователь скачивает `.dmg` и заменяет программу в «Программах». Mac-файлов в релизе шесть: `PDFwright-Mac-AppleSilicon.dmg`, `PDFwright-Mac-Intel.dmg`, `PDFwright-Portable-Mac-AppleSilicon.zip`, `PDFwright-Portable-Mac-Intel.zip`, `latest-mac.yml` (описывает оба `.zip` и оба `.dmg`) и `SHA256SUMS-Mac.txt`. Имена менять нельзя: на них ссылаются `latest-mac.yml` и README.

electron-builder подставляет процессор в имя файла только как arm64/x64, поэтому `scripts/build-release-mac.sh` собирает каждый процессор отдельным запуском в свою папку (`build/mac-arm64`, `build/mac-x64`), а `scripts/mac-release-files.mjs` сверяет оба `latest-mac.yml` с файлами (размер и sha512) и сливает их в один, с `.zip` для Apple Silicon первым. Блок-карты Mac-файлов не публикуются: Mac-версия не скачивает обновления сама.

## Первый выпуск 1.0.0

Версия в `package.json` уже 1.0.0, поэтому `npm version` не нужен: тег ставится вручную на проверенный коммит `main` с зелёным CI.

```bash
git tag -a v1.0.0 -m "Версия 1.0.0"
git push origin v1.0.0
```

Дальше — с шага 4 следующего раздела: workflow соберёт и опубликует релиз.

## Mac-файлы в релиз 1.0.0

Релиз v1.0.0 вышел только с Windows-файлами. Mac-файлы докладываются в него один раз отдельным тегом `mac-v1.0.0` (docs/MACOS_PLAN.md, правило 5); Windows-файлы, заголовок релиза и отметка latest при этом не меняются, и пользователи Windows не получают пустого обновления.

1. Убедитесь, что на `main` зелёные Windows CI и Mac CI, а версия в `package.json` — 1.0.0.
2. Проверьте выпуск без загрузки: **Actions → Release PDFwright for Mac → Run workflow** на ветке `main`. Workflow соберёт шесть Mac-файлов на двух Mac-машинах, сверит релиз v1.0.0 (пять Windows-файлов на месте) и покажет, какие файлы были бы загружены и как изменится описание. Сам релиз он не трогает.
3. Поставьте тег и отправьте его:

   ```bash
   git tag -a mac-v1.0.0 -m "PDFwright 1.0.0 для Mac"
   git push origin mac-v1.0.0
   ```

4. `.github/workflows/release-mac.yml` проверит, что тег совпадает с версией в `package.json`, соберёт файлы командой `bash scripts/build-release-mac.sh` на `macos-latest` (Apple Silicon) и `macos-15-intel` (Intel), загрузит шесть Mac-файлов в релиз v1.0.0 и добавит к его описанию раздел «Для Mac» из [installer/release-section-mac.md](installer/release-section-mac.md). Это займёт примерно 20–30 минут.
5. Откройте релиз v1.0.0: прежние пять Windows-файлов на месте, добавлены шесть Mac-файлов, в описании есть раздел «Для Mac». Скачайте Mac-файлы и сверьте суммы: `shasum -a 256 -c SHA256SUMS-Mac.txt`.

Если workflow упал после загрузки части файлов, запустите его заново (**Re-run all jobs**): Mac-файлы с теми же именами заменяются, Windows-файлы не трогаются. Дальше Mac-версия выходит только вместе с Windows-версией по общему тегу `v*`.

## Выпустить новую версию

1. Обновите [RELEASE_NOTES.md](RELEASE_NOTES.md): он целиком станет описанием релиза. Раздел «Для Mac» (файлы и первый запуск) workflow добавит сам из [installer/release-section-mac.md](installer/release-section-mac.md), если в RELEASE_NOTES.md нет своего раздела `## Для Mac`.
2. Поднимите версию и создайте тег одной командой (она же делает коммит):

   ```bash
   npm version 1.0.1 -m "Версия %s"
   ```

3. Отправьте коммит вместе с тегом:

   ```bash
   git push --follow-tags
   ```

4. GitHub Actions (`.github/workflows/release.yml`) проверит, что тег совпадает с версией в `package.json`, соберёт Windows-файлы командой `bash scripts/build-release.sh`, а Mac-файлы — командой `bash scripts/build-release-mac.sh` на двух Mac-машинах (`.github/workflows/mac-release-build.yml`). Когда готовы обе сборки, он сразу опубликует релиз `PDFwright v1.0.1` с одиннадцатью файлами (пять Windows и шесть Mac) как последний (latest). Если упала любая из сборок, релиз не публикуется. Примерно через 25–30 минут после push релиз появится на [странице релизов](https://github.com/iHoooK/PDFwright/releases), а установленные программы предупредят о новой версии при следующей проверке.
5. Откройте релиз и проверьте описание, одиннадцать файлов и тег. Если что-то не так, удалите релиз и тег на GitHub, исправьте ошибку и выпустите следующую версию: обновлятор видит только опубликованные релизы.

Ставьте тег только на проверенную версию: релиз публикуется без черновика.

## Выпустить вручную

Если Actions недоступен, соберите релиз локально из Git Bash:

```bash
bash scripts/build-release.sh
```

Mac-файлы собираются только на Mac (Node.js 24 и Xcode Command Line Tools), в Терминале из корня проекта на том же коммите:

```bash
bash scripts/build-release-mac.sh
```

Создайте релиз на GitHub руками: тег `v1.0.1` на том же коммите, заголовок `PDFwright v1.0.1`, описание из `RELEASE_NOTES.md` с разделом «Для Mac» (из `installer/release-section-mac.md`), и загрузите пять Windows-файлов и шесть Mac-файлов из папок `build/` обеих сборок. Имена файлов менять нельзя. Не используйте автоматический `Source code (zip)` вместо portable-версии.

## Проверить опубликованный выпуск

- Запустите установленную предыдущую версию: примерно через 10 секунд должно появиться предупреждение о новой версии с размером установщика (или нажмите **Проверить обновления**). «Скачать и установить…» скачивает файл, показывает проверку sha512 и предлагает установить; после мастера программа запускается сама, настройки и недавние файлы сохраняются.
- На свежей версии проверка должна сообщить, что установлена актуальная версия.
- Portable-версия показывает ссылку на страницу релиза; обновляется распаковкой нового архива в новую папку. Данные лежат отдельно в `%APPDATA%\PDFwright`.
- На Mac предыдущая версия тоже предупреждает о новой, а кнопка открывает страницу релиза. Новая версия из `.dmg` перетаскивается в «Программы» с заменой; настройки в `~/Library/Application Support/PDFwright` сохраняются.

Подписи кода у установщика нет: при первом запуске SmartScreen может показать предупреждение «Неизвестный издатель». Это ожидаемо для 0.x и не влияет на проверку целостности обновлятором. Mac-версия подписана только ad-hoc (без Apple Developer ID и нотаризации): macOS один раз просит разрешить запуск, как описано в README, раздел «Для Mac».
