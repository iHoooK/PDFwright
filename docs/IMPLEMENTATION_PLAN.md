# PDFwright Implementation Plan

Формат: ✅ - сделано, `[ ]` - не сделано, `[~]` - в работе.

Сводка: план описывает создание PDFwright — локальной Windows-программы для просмотра, редактирования и обработки PDF (страницы, аннотации, формы, конвертация), с установщиком, portable-версией, проверкой обновлений через GitHub Releases и разделом «О разработчике» по образцу соседней утилиты ЛовиКадр (`iHoooK/lovi-kadr`). План доводит проект до публичного релиза 0.1.0.

Не входит в этот план: macOS и Linux, мобильные версии, облачные функции и аккаунты, правка существующего текста с перестройкой абзацев «как в Word», OCR, цифровые сертификаты подписи, публикация в Microsoft Store.

Правило сопровождения: после реализации каждого пункта или фазы обновляй статус чекбокса и добавляй краткую сводку: что сделано, какие файлы/экраны/контракты затронуты, к чему это привело. Это живой документ.

Текущая отправная точка: папка `D:\Projects\Utils\PDFwright` пуста, локального git-репозитория нет. На GitHub создан пустой публичный репозиторий `iHoooK/PDFwright` (ветка `main`), SSH-доступ к GitHub с этой машины работает. Локально установлены Git 2.55, Node.js 24 LTS, npm 11, Python 3.15; .NET SDK, Rust, Inno Setup, NSIS не установлены. Образец механики установки, обновления и «О разработчике» — ЛовиКадр: C# WPF, Inno Setup, `GET /repos/.../releases/latest`, проверка SHA-256 из `digest` релиза, проверка только по кнопке, PRIVACY.md, RELEASING.md, GitHub Actions на `windows-latest`.

## Фаза 1. Дизайн-система и app shell

Цель: выбрать визуальное направление и собрать каркас интерфейса до подключения PDF-логики, чтобы дальнейшие экраны строились на одной системе.

Теория: документный редактор — «тихий» интерфейс: контент (страница) должен быть самым ярким элементом, панели и инструменты — приглушёнными, с крупными зонами клика и предсказуемыми горячими клавишами. Дизайн фиксируется в `docs/DESIGN.md` (скилл `impeccable shape`), компоненты собираются по `frontend-design-kit`, финальная полировка — `impeccable craft`.

Что будет реализовано:

## Фаза 2. Просмотр PDF

Цель: сделать быстрый и надёжный просмотрщик, который можно использовать как основной для .pdf.

Теория: pdf.js рендерит страницы в canvas в worker-потоке и кладёт поверх прозрачный текстовый слой для выделения и поиска. Для скорости рендерятся только видимые страницы и соседние, остальные держат плейсхолдер нужного размера; результаты кэшируются по паре (страница, масштаб).

Что будет реализовано:

- Непрерывная прокрутка, режимы «одна страница» и «разворот», zoom (по ширине, по странице, проценты, Ctrl+колесо), поворот вида.

- Боковая панель: миниатюры, закладки (outline), результаты поиска.
- Печать через системный диалог; свойства документа (метаданные, размер, число страниц).
- Защищённые паролем PDF: запрос пароля при открытии.

## Фаза 3. Страницы и файлы: объединение, разделение, перестановка, сохранение

Цель: закрыть самые частые задачи редактирования PDF — манипуляции страницами и файлами — с надёжным сохранением.

Теория: pdf-lib загружает документ, копирует нужные страницы в новый документ и сохраняет байты. Все операции — чистые функции `(input: Uint8Array, params) => Promise<Uint8Array>` в `src/shared/pdf-ops/`; UI лишь собирает параметры. Сохранение атомарное: запись во временный файл рядом и переименование, чтобы не повредить исходник при сбое.

Что будет реализовано:

- Режим «Страницы»: сетка миниатюр с перетаскиванием, множественный выбор, поворот, удаление, вставка пустой страницы или страниц из другого PDF, извлечение выбранных в новый файл, дублирование.
- Инструмент «Объединить»: список файлов с порядком, предпросмотр, результат в новый файл.
- Инструмент «Разделить»: по диапазонам, по N страниц, на отдельные файлы, по закладкам.
- Сохранить / Сохранить как, индикатор несохранённых изменений, предупреждение при закрытии, резервная копия исходника по настройке.

Результат: пользователь объединяет, разделяет и переупорядочивает PDF без сторонних сервисов; результат открывается в Adobe Reader и браузере без ошибок.

## Фаза 10. Правка содержимого страниц на MuPDF (релиз 0.2.0)

Порядок: 10.1–10.5 идут параллельно с фазой 4 в отдельной сессии (только движок и тесты, без интерфейса); 10.6–10.8 — после слияния фазы 4 и движка.

Цель: править то, что уже есть в документе, а не только рисовать поверх: удалять и заменять текст, удалять, заменять и перемещать картинки, вычищать области.

Теория: страница PDF — это поток команд «нарисуй глиф в точке», «нарисуй картинку в прямоугольнике». Абзацев и строк в файле нет, поэтому текст нельзя «перенабрать» с перестройкой. MuPDF умеет три нужные вещи: отдать структуру страницы (строки текста с координатами, шрифтом, размером и цветом; картинки с прямоугольниками), по-настоящему вырезать содержимое внутри прямоугольника (redaction: текст и картинки удаляются из файла, а не закрашиваются) и дописать на страницу новый текст и картинки. Замена текста = вырезать старую строку + написать новую тем же шрифтом, если в нём есть нужные глифы, иначе встроенным шрифтом с кириллицей того же размера и цвета. MuPDF работает в WASM и в Node, и в браузере; в renderer движок выполняется в Web Worker, чтобы не блокировать интерфейс.

Что будет реализовано:

- Движок `pdf-content` поверх `mupdf`: чистые асинхронные функции над `Uint8Array`, как `pdf-ops`.
- Выбор существующих объектов страницы инструментом «Выделение»: строка текста или картинка подсвечивается рамкой.
- Действия над выбранным: удалить, заменить текст, заменить картинку, переместить картинку; ластик области (вырезать всё в прямоугольнике).
- Всё через ту же историю отмены и сохранение, что и остальные правки.

Результат: опечатку в строке можно исправить, лишнюю картинку или блок текста — удалить так, что их нет в файле (не находятся поиском), картинку — заменить или сдвинуть.

## Фаза 12. Несколько окон и восстановление вкладок (релиз 0.3.0)

Шифрование возвращается при записи файла: у файла, открытого паролем, `relockPdf` переносит объекты правленой копии под теми же номерами в исходный документ, открытый паролем, и пишет его с прежним ключом — сохраняются оба пароля и ограничения, даже если известен только пароль на открытие (без правок пишется сам исходный файл); новый пароль — `protectPdf` (AES-256, пароль владельца с запретом печати и копирования по желанию; параметры MuPDF передаются JSON-объектом, поэтому пароли с запятыми и кириллицей работают). Пароль живёт только в памяти вкладки (`DocTab.protection`), в настройки, сеанс, недавние файлы и журнал не попадает; текст ошибки шифрования MuPDF заменяется общим сообщением.
