# PDFwright для macOS — план реализации

Формат: ✅ — сделано, `[ ]` — не сделано, `[~]` — в работе.

Сводка: выпустить PDFwright для Mac поверх Windows-версии 1.0.0 — тот же код и те же функции, установщик `.dmg` и переносная версия `.zip` для Apple Silicon и Intel, без подписи Apple, с инструкцией «Всё равно открыть». Mac-файлы докладываются в уже опубликованный релиз v1.0.0 на GitHub.

Правило сопровождения: после каждого пункта обновляй статус и добавляй короткую сводку (что сделано, какие файлы затронуты, чем проверено). Это живой документ.

## Главные правила

1. **Windows-версия не меняется.** Код один, а всё новое срабатывает только на macOS (`process.platform === 'darwin'` в main, признак платформы из preload в renderer). Не трогаются: разделы `win` и `nsis` в `electron-builder.yml`, папка `installer/`, `scripts/build-release.sh`, `scripts/package-release.ps1`, Windows-задания в `.github/workflows/build.yml` и `release.yml`, поле `description` в `package.json` (оно попадает в свойства `PDFwright.exe`).
   Разрешённые автором изменения, видимые в Windows:
   - текст «О разработчике» (решение 2026-10-29: «создаю сайты, игры и программы», без уточнения, для всех версий);
   - строка про папку данных Mac в `PRIVACY.md` и `docs/en/PRIVACY.md` (эти тексты встроены в окно «Лицензии и приватность»).
2. **Ничего не устанавливать на компьютер автора.** Новых программ и npm-зависимостей нет; если без зависимости не обойтись — сначала спросить автора. Всё, что требует macOS (сборка `.dmg`, тесты на Mac, снимки экрана), выполняют Mac-машины GitHub Actions: для публичного репозитория это бесплатно.
3. **GitHub.** Рабочие ветки `mac/…` и служебную ветку `ci/mac-results` сессии отправляют сами (разрешено автором 2026-10-29). Слияние в `main`, отправка `main`, теги и релизы — только после «да» автора.
4. **Проверка «Windows не изменилась»** после каждого слияния:
   - `npm run check`, `npm run build`, `npm run test:e2e` локально и зелёный Windows CI;
   - unit-тест, который сравнивает шаблон меню для Windows с прежним;
   - сравнение снимков интерфейса Windows (`npm run docs:shots`, `npm run site:shots`) с эталоном фазы M0 — отличаться может только экран «О разработчике»;
   - `git diff` по защищённым файлам из правила 1 пуст.
5. **Одно обновление — для всех систем сразу** (решение автора 2026-10-29). После выхода Mac-версии любая правка делается один раз в общем коде и выходит одним тегом `v*`: в одном релизе собираются и Windows-, и Mac-файлы. Отдельных Mac-версий и Mac-веток кода нет. Единственное исключение — первая доставка Mac-файлов в уже опубликованный релиз v1.0.0 (тег `mac-v1.0.0`).

## Отправная точка (2026-10-29)

- Опубликован релиз v1.0.0: `PDFwright-Setup-x64.exe`, `.blockmap`, `latest.yml`, `PDFwright-Portable-x64.zip`, `SHA256SUMS.txt`. Собран из коммита `1618096`.
- На `main` после релиза есть коммит `41adb7e` («Снимки для сайта и исправление раскладки окна»). Его Windows CI упал на e2e `tests/e2e/forms.e2e.ts:174`: поле формы не получило значение «Мария».
- Electron 45: нужна macOS 13 Ventura или новее. electron-builder 26.18.
- Нативных модулей нет: pdf.js, MuPDF и Tesseract работают на WebAssembly, поэтому под Mac ничего не перекомпилируется.
- Сочетания в меню заданы как `CmdOrCtrl`, а горячие клавиши интерфейса принимают и Ctrl, и ⌘.
- Без входа в GitHub (проверено): аннотации с ошибками тестов читаются через публичный API, а логи и артефакты сборок — нет (ответ 403). Поэтому снимки и отчёты с Mac сборка кладёт в служебную ветку `ci/mac-results`, откуда их забирает `git fetch` по SSH.

## Риски и откат

- **Случайно изменилась Windows-версия.** Защита — проверки правила 4 после каждого слияния. Откат — `git revert` коммита слияния; опубликованный Windows-релиз v1.0.0 эти правки не затрагивают.
- **`fileAssociations` попал в установщик Windows.** Задаётся только внутри `mac`; M2.2 сверяет Windows-сборку с эталоном.
- **Нет ad-hoc подписи — «Программа повреждена».** `codesign --verify` в CI, явный `identity: "-"`.
- **Apple ужесточит Gatekeeper.** Инструкция в README и запасная команда `xattr`; при необходимости — вернуться к Apple Developer Program.
- **Без живого Mac не проверить печать, Finder, жесты и первый запуск из интернета.** Эти пункты закрывает M4; до неё Mac-версия не анонсируется.
- **Mac-машины GitHub новее, чем у пользователей** (macos-latest — macOS 26). Минимальная версия зашита в `Info.plist`; поведение на 13–15 проверяет автор или пользователи.
- **Intel-машины GitHub исчезнут** (примерно в августе 2027). Тогда Intel-сборка останется без автоматической проверки — решить к тому времени.

## Не входит

Подпись и нотаризация Apple, Mac App Store, Homebrew, Linux, автоматическая установка обновлений на Mac, переделка дизайна под стиль macOS сверх перечисленного (Windows 11 Fluent остаётся).
